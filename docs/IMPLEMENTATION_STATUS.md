## 運用上の制限・未検証

- Raspberry Pi 5、物理タッチモニター、実際のiOS／Android、LANの別ハードウェアでは未検証。スマホ確認はブラウザーの画面サイズ変更によるもの。
- 時刻入力とカレンダー表示は日本時間に限定。APIもAsia/Tokyoのみ受理する。別タイムゾーン対応は将来の拡張対象。
- WebSocket配信は単一プロセスなので、サーバーは1ワーカーで起動する。
- 外観設定は自動保存から明示的な保存へ変更。失敗や競合を確認できるよう、設定画面上の「外観を保存」で確定する。
- 旧公開版のlocalStorageの自動移行は行わない。元データは保持されており、実データがある場合は別途移行する。
- 初期設定はlocalhostのみ。初期設定後にLAN用起動へ切り替える。
- 長期連続稼働・負荷・障害復旧の実機検証、HTTPS、サービス自動起動、本番監視は未実施。
- 天気・交通はサンプル、写真・位置共有・音声は未実装。Google連携もPhase 2以降。
- オフラインの編集やローカル書き込みキューは提供しない。

Phase 2へはCalendarの外部IDフィールド、個別のAPI／データモジュール、既存の未実装専用画面を引き継ぐ。ユーザー管理の長期仕様書をエージェント側で書き換えず、仕様の変更が必要な場合はユーザーへ提案する。

実装時の参考: [FastAPI WebSockets](https://fastapi.tiangolo.com/advanced/websockets/)、[SQLAlchemyのバージョン管理](https://docs.sqlalchemy.org/en/20/orm/versioning.html)。
