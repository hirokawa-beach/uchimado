# 認証・アカウント仕様

2026-11-08のユーザー指示を、Phase 1の認証・権限管理に優先して適用する。
ユーザー管理の `PROJECT_SPEC.md` は変更しない。本書と `PHASE_1.md` の更新で今回の変更を記録する。

## 家族の通常利用

- 家庭内LANの通常画面はログインなしで開く。管理者未設定でも家族共通の予定・タスク・メモを利用できる。
- 家族プロフィールは名前・使用状態・IDを持ち、パスワード・PIN・パターン・管理者ロールを持たない。
- 画面の「作成者として使う名前」で選択する。作成者の自己申告であり、本人確認の証拠にはしない。予定・タスクの担当者は編集画面で別に選ぶ。
- 予定・タスクの担当はプロフィールIDで管理する。名前変更後も同じ人を指す。作成者は選択中のプロフィールIDを記録する。
- プロフィールの選択IDだけを端末のlocalStorageへ保存する。管理者認証情報はlocalStorageへ保存しない。
- 作成・編集・使用停止は管理者のみ。使用停止しても過去の作成者や担当者の記録は保持する。

## 管理者

- 管理者専用アカウントはインスタンスに1つ。家族プロフィールと独立し、旧ユーザーのadminロールも引き継がない。
- 初回設定はサーバーPCのlocalhostだけで実行可能。既存の管理者が設定済みなら初回設定APIを拒否する。
- 3×3の点を4個以上・各点1回まで結ぶ。未選択の中間点をまたぐ直線は、中間点を自動追加する。
- マウス／タッチはPointer Eventsとpointer captureを共用し、高速移動で通過した点も順に取り込む。順次クリックやキーボード入力にも対応する。
- パターンは個別のソルト付きscrypt（N=2^17, r=8, p=1）でハッシュ化する。
- 解除後のランダムなセッショントークンはHttpOnly・SameSite=Strict Cookieに保存し、DBにはSHA-256ハッシュだけを保存する。
- 管理者セッションは発行から15分の固定期限。API側で期限・認証世代を確認し、期限を自動延長しない。手動ロックも可能。
- プロフィールを切り替えても、管理者権限の取得・失効は起こらない。
- パターンの変更・復旧・ローカル回復コード再発行で、全管理者セッションを失効させる。

## 管理API

- プロフィールの追加・変更・使用停止、家族名変更、DBバックアップ・復元、管理者パターン変更は管理者解除が必要。
- ホームの外観・背景・ウィジェット配置は通常の家族利用で変更できる。端末種別ごとの家族共通設定として保存し、同時編集のバージョン検証は維持する。
- APIはプロフィールIDやリクエストのrole指定を権限判定に使用しない。
- 管理者専用APIの認証確認と管理操作をSQLiteの書き込みトランザクション内で直列化し、認証更新との競合を避ける。
- DB復元はサーバー停止中のローカルCLIで実行し、現在の管理者パターンを確認する。LANからDBを置き換える復元APIは提供しない。
- バックアップ復元で古いパターン・使用済み回復コード・セッションを復活させない。現在の管理者認証情報を引き継ぎ、全セッションを失効させる。
- ブラウザーからの更新は同一オリジン・独自ヘッダーを確認する。管理者APIはLAN内でも必ず認証する。

## 試行回数と復旧

- パターン認証は全体／接続元とも15分間に5回失敗すると制限する。別IPや再起動で全体制限を回避できない。
- 回復コードは独立した全体／接続元制限（15分間に3回失敗）を持つ。
- 初回設定、パターン変更、復旧時に192ビットのランダムな回復コードを発行する。DBにはコードのダイジェストだけを保存する。
- 回復コードは一度だけ画面に表示し、任意でテキストファイルへ保存できる。保管確認後に画面を閉じる。
- コードによる復旧は新パターンの2回入力を要求する。成功後は旧コードを失効し、新しいコードを発行する。自動で管理者解除はしない。
- コードも紛失した場合は、サーバーを停止してOS上のDB保守権限を持つ管理者が `python -m backend.manage issue-admin-recovery --server-stopped` を実行する。新コードをその端末のコンソールに表示し、旧コードと全管理者セッションを失効させる。
- パターンや回復コード、そのハッシュを監査履歴や通常ログへ含めない。

## 移行と非公開データ

- Alembic `0002_profiles_admin` で更新する。旧 `0001_core` DBは更新前に整合したSQLiteバックアップを作る。
- 旧ユーザーをプロフィールへ移行し、ID・名前・作成者・担当者の関係を保持する。
- 旧セッションを全失効し、旧パスワードハッシュを無効値へ置換する。旧ログインAPI・ユーザー管理APIは廃止する。
- 旧users／membershipsは既存非公開データの外部キー等を保全するためのアーカイブとして残し、新しい認証やプロフィール作成には使用しない。
- 旧非公開レコード・個人カレンダー・個人設定・個人完了履歴はDBに残し、通常APIでは返さない。プロフィールを選択しても、管理者を解除しても表示しない。
- 新規の非公開レコード作成も拒否する。個人向け認証が必要になった場合は、別途本人確認方式を設計する。
- 以前の共有端末用の配置・外観だけを家族共通設定に引き継ぐ。個人設定を共通設定へ自動公開しない。

- TypeScriptチェックとVite本番ビルド成功。
- ブラウザー実操作で、ログインなしのホーム、プロフィール作成・選択、ロック中のメモ保存と作成者表示、パターン設定・変更・復旧、マウスドラッグ解除、回復コードの表示と復旧後に自動解除しない動作を確認。
