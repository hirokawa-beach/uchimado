# Phase 1 実装計画

> 初回実装時の計画です。認証・アカウント部分は後続の [AUTH_ACCOUNT_SPEC](AUTH_ACCOUNT_SPEC.md) に置き換わりました。

基準はユーザー管理の `PROJECT_SPEC.md` と `PHASE_1.md`。両ファイルの本文は変更しない。

## 既存コードの調査

- 旧プロトタイプは別フォルダーの `outputs/homeboard` に存在。ソース・写真・依存ロックをこのチェックアウトへ複製し、元ファイルは保持。
- React 19 / TypeScript / Vite / Tailwind、Lucide、Radix Dialog。ホーム、ドック、ランチャー、月週日カレンダー、画面キーボード、ウィジェット配置を再利用。
- 保存は `homeboard.v1.*` のlocalStorage。タスクは完了切替、メモは単一文字列で、専用画面は未実装。バックエンド・認証・同期・テストは未実装。
- デザインの再構築は行わず、名称をKagiroiへ変更。天気・交通などはサンプルのまま明示。

## 実装順序

1. 既存フロントエンド取り込み・名称変更・ローカル起動構成。
2. FastAPI / SQLAlchemy / Alembic / SQLite、セッション認証と共有端末モード。
3. 家族・個人カレンダー、繰り返しと特定回の例外、タスク完了履歴、掲示板CRUD。
4. API接続、バージョンによる競合検出、WebSocket再接続・再取得、設定の端末種別別保存。
5. API・フロントエンド検証、ビルド、FHD/スマホの表示確認、起動・バックアップ・復元手順。

## 実装上の方針

- DBは起動時にAlembic upgradeのみを実行し、ユーザーデータを自動初期化しない。
- 個人データは所有者のみ操作可能。管理者であっても他者の個人データを取得できない。
- 共有端末への切替は管理者が行い、本人セッションを破棄する。共有端末には個人データ・管理権限を持たせない。
- 予定日時はIANAタイムゾーンと現地日付・時刻で保持。Phase 1の画面表示はAsia/Tokyoを基準とする。
- シリーズ更新は全体置換で例外をクリアする。特定回の移動・変更・取消は元の開始日をキーに保持。
- SQLiteのオンラインバックアップを提供。復元は停止中にCLIで実行し、既存DBの退避とセッション失効を行う。
- LAN内の同一オリジンで提供し、外部公開・既存公開サイトの変更は行わない。
