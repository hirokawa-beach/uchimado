# uchimado — Phase 1 実装指示書
Core Foundation

## 1. 目的

既存のHomeBoardプロトタイプを、正式名称「uchimado」として本格的な家庭用Webアプリケーションに発展させてください。

本プロジェクトの製品仕様・デザインシステム・長期ロードマップは `docs/PROJECT_SPEC.md` を参照してください。

**今回の実装対象はPhase 1のみです。**

Phase 2〜4は将来の開発計画です。今回はそれらの実装を要求しませんが、後から拡張しやすい構成にしてください。

## 2. 既存実装の調査

作業開始前に現在のリポジトリを調査してください。

- 使用技術と依存関係
- 実装済み画面・コンポーネント
- ホーム・アプリランチャー・ドック
- カレンダー・タスク・メモの実装状況
- ウィジェット配置・テーマ設定

調査結果をもとに実装計画を立て、既存コードを最大限再利用してください。

## 3. リブランディング

名称をHomeBoardから **uchimado** に変更してください。

- 画面上のブランド表記
- ブラウザータイトル
- PWAマニフェスト
- README
- 必要なアプリケーション識別子

デザインシステム名称は **Kagiroi** とします。

既存のFloating Surfaceをベースにしたデザインを維持し、名前の変更を理由に大幅なUIの改修を行わないでください。

旧プロトタイプの一時データとの完全な互換性は不要ですが、保持すべきユーザーデータがある場合は事前に保護してください。

## 4. バックエンド・データベース

既存フロントエンドに、次のバックエンドを追加してください。

- Python + FastAPI
- SQLite
- SQLAlchemy
- Alembic
- REST API
- WebSocketによる変更通知

最低限、以下のデータ構造を検討してください。

- Family / Profile / AdminCredential / AdminSession（旧User等は移行データ保全用）

必要な監査・更新履歴も保持できるようにしてください。

SQLiteのマイグレーション、トランザクション管理、基本バックアップに対応してください。

## 5. 認証・アカウント管理（2026-11-08変更）

詳細は `docs/AUTH_ACCOUNT_SPEC.md` を参照してください。

- 通常の家族利用はログイン不要。プロフィールにパスワードやパターンを設定しない。
- 家族プロフィールは担当者・作成者を区別するために使い、選択・切替を認証として扱わない。
- プロフィールとは独立した管理者専用アカウントを1つ用意し、3×3のパターンロックで解除する。
- マウス・タッチ両方のパターン入力に対応する。
- プロフィール管理・システム設定・バックアップ・復元は管理者だけが実行できる。
- 管理APIで権限と期限を確認する。解除は15分で失効し、手動ロックも提供する。
- パターンをソルト付きscryptで保存し、永続化した全体・接続元の試行回数制限を設ける。
- 一回限りの回復コード、サーバー上のローカル保守による復旧を提供する。
- 既存の非公開データは保持し、プロフィール選択や管理者解除だけでは開示しない。
- 初期運用は家庭内LAN限定。外部公開向けの認証は本Phaseに追加しない。

## 6. カレンダー

以下を実際に動作する形で実装してください。

- 月・週・日表示
- 予定の作成・編集・削除
- 終日予定
- 繰り返し予定
- 説明・場所・色
- 家族共通カレンダー。旧個人データは保全し、非認証プロフィールからは開示しない。
- ホームウィジェットとの連動
- 複数端末への変更反映

繰り返し予定では、特定回とシリーズ全体の扱いを明確にしてください。

日時・タイムゾーンを適切に管理してください。

Googleカレンダー連携はPhase 2で実装するため、今回は必要な拡張余地のみ確保してください。

## 11. UI・UX

1920×1080の壁掛けタッチモニターを基準に、スマートフォンにも対応してください。

- 48×48px以上の主要操作領域
- タッチだけで予定・タスク・メモを編集可能
- フローティング編集パネル
- ソフトウェアキーボードを考慮
- 未保存変更の保護
- ローディング・エラー表示
- アニメーション軽減設定

既存の画面構成やデザインを不要に変更しないでください。

ただし、未実装の機能を実際に動作しているように表示しないでください。

## 13. 運用・安全性

- Windows開発環境で起動できること
- Raspberry Pi 5での将来運用を考慮すること
- LAN内から利用できること
- DBバックアップ・復元の基本手順
- APIの認証・認可
- 入力検証と適切なエラー処理

## 14. 検証・完了条件

以下を実際に検証してください。

1. 通常利用はログインなしで開始でき、管理者のパターン解除・ロックが動作する。
2. プロフィール選択では管理権限を取得できず、旧個人データも開示されない。管理APIは未解除・期限切れを拒否する。
3. カレンダーの予定を作成・編集・削除できる。
4. 繰り返し予定が正しく扱える。
5. タスクを作成・編集・完了できる。
6. メモを作成・編集・削除できる。
7. ホームに実データが表示される。
8. データが再読み込み・サーバー再起動後も維持される。
9. 複数端末間で変更が反映される。
10. ウィジェット配置が保存される。
11. 1920×1080で主要画面が正常に表示される。
12. スマートフォンでも基本操作ができる。
13. 既存のKagiroiデザインが維持される。
14. フロントエンド・バックエンドのテストが成功する。

可能な範囲でAPIテストとE2Eテストを追加してください。

実機で検証できない項目は未検証として報告してください。
