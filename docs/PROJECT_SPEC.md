# uchimado — プロジェクト総合仕様書・ロードマップ
Version 1.0

## 1. プロジェクト概要

**製品名：** uchimado（うちまど）  
**旧称：** HomeBoard  
**キャッチコピー：** 暮らしを映す、もうひとつの窓。  
**デザインシステム：** Kagiroi（かぎろひ）

uchimadoは、家族の日常生活に必要な情報を一元的に管理・共有する、家庭向け情報プラットフォームである。

カレンダー、天気、タスク、メモ、交通情報、写真、家族の現在地などをまとめ、家庭内に設置したタッチディスプレイを中心に、スマートフォンやPCからも利用できることを目指す。

uchimadoは「内窓」から来たもの。実際の内窓が断熱や防犯など家の基本機能をアップグレードするように、このダッシュボードが日常生活をサポートし、アップグレードするという意味がある。

### 製品の基本理念

- **Information：** 必要な情報を自然に見渡せる
- **Organization：** 家族の予定やタスクを整理・共有できる
- **Interaction：** 壁掛け画面からも直接操作・編集できる
- **Continuity：** 端末や利用場所が変わっても情報がつながる
- **Calmness：** 暮らしになじみ、長時間表示しても疲れない

本製品はスマートホームの家電操作を主目的としない。スマート家電が存在しない家庭でも価値を提供できることを重視する。

## 2. 対象プラットフォーム

### 壁掛け端末

- Raspberry Pi 5（4GB）
- 15.6〜18.5インチ程度のタッチディスプレイ
- フルHD（1920×1080）横向きを基準
- Chromiumキオスクモード
- 家庭内LANを通じたアクセス
- 常時稼働

壁掛け端末でも、予定・タスク・メモなどの追加、編集、削除を行えるものとする。

### その他の端末

- Windows、macOS、LinuxのWebブラウザー
- Android、iOSのブラウザー
- スマートフォン向けPWA

主要機能を共通化しつつ、各画面サイズに適したUIを提供する。

## 3. デザインシステム — Kagiroi

プロトタイプでデザインはいったんは確定しているので、それに従うこと。

### 名前と思想

Kagiroi（かぎろひ）は、夜明けの光を連想させる古い日本語に由来する。

光の透過、反射、柔らかな陰影、奥行き、時間によって変化する表情を大切にする。

### デザイン方針

Microsoft Fluent DesignとGlassmorphismを参考とし、uchimado独自の表現へ発展させる。

- 写真をぼかした背景
- 半透明のガラス・アクリル調カード
- 控えめなハイライトと反射
- 自然なドロップシャドウ
- 整然としたカード型レイアウト
- フローティングドック
- アプリランチャー
- 滑らかで控えめなアニメーション

背景写真、透明度、影、角丸、配色などはデザイントークンで管理し、変更可能とする。

装飾よりも情報の読みやすさ、タッチ操作の確実性、Raspberry Pi上での軽快な動作を優先する。

### UIの階層

- Layer 0：背景・壁紙
- Layer 1：通常のウィジェット
- Layer 2：フローティングパネル・アプリランチャー
- Layer 3：モーダル・確認ダイアログ

## 4. アプリケーション構造

uchimadoはホーム画面と機能ごとの専用画面を持つ。

### Home

各機能の情報を要約して表示する。

標準では4〜6個程度の主要ウィジェットを配置し、過度に情報を詰め込まない。

ウィジェットの追加・削除・配置変更・サイズ変更を可能とする。

### Apps

各機能には独立した専用画面を設ける。

ホームのウィジェットまたはアプリランチャーから起動する。

### Floating Panels

予定・タスク・メモの編集などを行う操作用パネル。

複雑な操作では全画面編集UIに切り替える。

### Navigation

フローティングドックとアプリランチャーを標準とし、壁掛け・スマートフォンで適切な表示形式に切り替える。

## 5. 主要機能

### 5.1 カレンダー

- 月・週・日・一覧表示
- 家族共通・個人カレンダー
- 予定の作成・編集・削除
- 終日・繰り返し予定
- 家族ごとの色分け
- Googleカレンダー双方向同期

### 5.2 時計・天気

- 時計・日付・曜日
- 現在の天気・気温
- 降水確率・時間別・週間予報
- 地域設定

### 5.3 家族タスク

- 共有ToDo・買い物リスト
- 担当者・期限・優先度
- 繰り返しタスク
- 完了履歴

### 5.4 メモ・掲示板

- 家族への連絡事項
- 付箋型メモ・掲示板
- ピン留め・分類
- 有効期限・編集履歴

### 5.5 交通情報

- 登録した鉄道路線の運行情報
- 遅延・運転見合わせ・運休
- 公式情報へのリンク
- 情報の最終更新日時

### 5.6 写真

- 写真アップロード
- アルバム管理
- スライドショー
- フォトフレームモード
- 背景写真への設定

### 5.7 ウィジェット

- 追加・削除
- 移動・サイズ変更
- グリッドスナップ
- 表示内容の個別設定
- 端末種別ごとのレイアウト
- 配置情報の永続化

### 5.8 家族の現在地

- 明示的な同意に基づく位置共有
- 共有を許可したメンバーの地図表示
- 最終更新日時
- 個人別の公開範囲設定
- 共有の一時停止・終了

位置履歴は標準では保存せず、共有停止とデータ削除が容易に行えることを重視する。

### 5.9 音声アシスタント

- 音声による情報取得
- カレンダー・タスクの音声操作
- 音声応答
- 将来的な自然言語操作
- 初期方式はプッシュ・トゥ・トーク

## 6. 基本アーキテクチャ

推奨技術：

- Frontend：React / TypeScript / Vite
- Styling：Tailwind CSS
- Backend：FastAPI
- Database：SQLite
- ORM：SQLAlchemy
- DB Migration：Alembic
- API：REST
- リアルタイム通知：WebSocket
- モバイル対応：PWA

既存実装を最大限活用し、シンプルなモジュラーモノリス構成を基本とする。

外部サービス連携は独立したモジュールとして設計し、個別のサービス障害によってuchimado全体が利用不能にならないようにする。

## 7. 開発ロードマップ

### Phase 1 — Core Foundation

**目標：家庭内で実際に利用できる基本システムの構築**

- uchimadoへのリブランディング
- バックエンド・データベース
- アカウント・認証・権限管理
- カレンダー
- 家族タスク
- メモ・掲示板
- ホームの実データ連携
- ウィジェット設定保存
- 複数端末間の同期
- 基本バックアップ

完了基準：家族が予定・タスク・メモを共有・編集でき、再起動後もデータが保持されること。

### Phase 2 — Connected Experience

**目標：外部情報と写真機能の本格実装**

- Googleカレンダー双方向同期
- 天気API
- 鉄道運行情報
- 写真・アルバム
- スライドショー
- 背景・テーマ設定の拡充

完了基準：実際の天気、交通情報、外部カレンダー、写真を利用できること。

### Phase 3 — Family & Assistant

**目標：家族向け連携機能と音声操作の拡充**

- 同意に基づく現在地共有
- 地図・共有ステータス
- 音声認識
- 音声アシスタント
- 通知・リマインダー

完了基準：家族の情報共有と主要な音声操作が適切な権限管理のもとで利用できること。

### Phase 4 — Production & Expansion

**目標：長期運用可能な家庭用プラットフォームへ発展**

- Raspberry Pi 5常時稼働の最適化
- 起動・復旧・監視機構の強化
- HTTPS・安全な外部アクセス
- バックアップ・復元の高度化
- カスタムウィジェット
- プラグイン機構の検討
- 将来的なスマートホーム連携

完了基準：日常的に安定稼働し、データの保護・復元・機能拡張が行えること。

なお、基本的な認証・バックアップ・障害対応はPhase 4まで先送りしない。

## 8. 開発上の共通原則

- 既存のUI・コードを不必要に作り直さない。
- Kagiroiを全画面で一貫して使用する。
- 壁掛けタッチ操作を正式な利用方法として扱う。
- 家族共通データと個人データを分離する。
- API側でアクセス権限を検証する。
- 個人情報の表示・共有は最小限とする。
- 保存データはPhase 1以降、マイグレーションで維持する。
- 各機能を分離し、将来の拡張を容易にする。
- 実機未検証の性能や互換性を保証しない。
- 未実装機能は未実装であることを明示する。
